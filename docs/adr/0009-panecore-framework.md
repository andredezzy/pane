# The engine is PaneCore.framework, Chrome's own layer, with explicit exports

The engine is Chrome's own framework, built from Chromium's `chrome/` layer with `//pane` linked in (ADR 0004), under Pane's name and brand: `PaneCore.framework`. `chrome/app/theme/chromium/BRANDING` carries the Pane names and `com.pane.desktop`, which also names the helpers `Pane Helper (…)` and the framework bundle `com.pane.desktop.framework`. The framework's own name is not derived from branding everywhere, so patch 0001 (`engine/patches/0001-pane-framework.patch`) sets it in each place that builds it: `chrome/BUILD.gn` (`chrome_framework_name`), `chrome/common/chrome_constants.cc`, `chrome/app/chrome_exe_main_mac.cc`, `content/public/app/BUILD.gn` (libaperitif's install name), and `chrome/browser/web_applications/os_integration/mac/BUILD.gn` (app_mode_loader). The same patch names the engine's Keychain item "Pane Safe Storage" (ADR 0043).

The framework's exports are explicit. Chromium builds with hidden visibility, and the API the app links is marked `PANE_EXPORT` (`engine/pane/public/PaneExport.h`). Beside Chrome's own entry points, `chrome/app/framework.exports` lets `_OBJC_CLASS_$_Pane*`, `_OBJC_METACLASS_$_Pane*`, and `_Pane*` through, and `chrome/app/framework.order` must list every one of them by name, in order: `verify_order.py` fails the build otherwise. So every new exported class or constant goes into `framework.order`. `engine/scripts/update-exports.sh` writes that list from the built framework, in the linker's order; then the engine is rebuilt and patch 0001 regenerated (`engine/UPGRADING.md`). The app builds against the headers in `engine/pane/public/`, the `PaneCore` module.
