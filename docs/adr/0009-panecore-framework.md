# The engine is Chrome's own framework and layer, Pane's by its branding, and exports only Chrome's entry points

The engine is Chrome's own framework, built from Chromium's `chrome/` layer with `//pane` linked in (ADR 0004), under Pane's name and brand. `pane/BRANDING`, which `branding_file_path` in `chromium/args/release.gn` points to, carries the Pane names and the identifier `xyz.roundedcorners.pane` (`MAC_BUNDLE_ID`; `com.pane.desktop` until 0.14.0, ADR 0114), after which Chromium names everything: the app, `Pane.app`, and its loader; the helpers, `Pane Helper (…)`; the framework, `Pane Framework.framework`; and its bundle, `xyz.roundedcorners.pane.framework`. It was `PaneCore.framework` until the review of 0.18.0, a name set in five of Chromium's files for no reason but the name (ADR 0004), and an update replaces the whole bundle. The engine archives keep their `PaneCore-` names (ADR 0049). The same patch names the engine's Keychain item "Pane Safe Storage" (ADR 0043).

The framework exports Chrome's own entry points and nothing else, as Chromium builds it: `_ChromeMain`, which Chromium's loader and helpers call, and the two entries Chrome's web apps' shims call (`_ChromeAppModeStart_v8`, `_ChromeWebAppShortcutCopierMain`). Pane's UI is inside the framework (ADR 0124), so nothing outside it links Pane's code. `chrome/app/framework.exports` is Chromium's own, and so is the check beside it in `chrome/BUILD.gn` (`verify_order.py`), which fails the build if the framework exports anything `chrome/app/framework.order` doesn't list, in its order.

Until the cutover to Views, the Swift app linked the framework and called Pane's Objective-C API in it (`pane/public`, the `PaneCore` module, `import PaneCore`), marked `PANE_EXPORT`: patch 0001 let `_OBJC_CLASS_$_Pane*`, `_OBJC_METACLASS_$_Pane*`, and `_Pane*` through `framework.exports`, and turned the order check off, since those exports came after `_ChromeMain`. Before the review of 0.18.0, `framework.order` had to list every one of them, in order (`scripts/update-exports.sh` wrote the list), which took a second build for each new class and 46 lines of patch. The API and its exports went with the Swift app, and `framework.exports` and the order check went back to Chromium's at 0.20.0 (ADR 0124), `chrome/BUILD.gn` keeping only `//pane` in the framework: the patches edit one Chromium file fewer.

## How it is checked

- **The build:** `verify_chrome_framework_order` runs with every build of `chrome`, and fails on an export Chromium doesn't list.
- **The exports:** `nm -jUng "Pane Framework.framework/Versions/Current/Pane Framework"` lists `_ChromeAppModeStart_v8`, `_ChromeWebAppShortcutCopierMain`, and `_ChromeMain`, and nothing of Pane's (2026-11-11).
