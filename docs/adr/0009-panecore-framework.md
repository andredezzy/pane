# The engine is PaneCore.framework, Chrome's own layer, with explicit exports

The engine is Chrome's own framework, built from Chromium's `chrome/` layer with `//pane` linked in (ADR 0004), under Pane's name and brand: `PaneCore.framework`. `engine/pane/BRANDING`, which `branding_file_path` in `engine/args/release.gn` points to, carries the Pane names and the identifier `xyz.roundedcorners.pane` (`MAC_BUNDLE_ID`; `com.pane.desktop` until 0.14.0, ADR 0114), after which Chromium names the helpers, `Pane Helper (…)`, and the framework bundle, `xyz.roundedcorners.pane.framework`. The framework's own name is not derived from branding everywhere, so patch 0001 (`engine/patches/0001-pane-framework.patch`) sets it in each place that builds it: `chrome/BUILD.gn` (`chrome_framework_name`), `chrome/common/chrome_constants.cc`, `chrome/app/chrome_exe_main_mac.cc`, `content/public/app/BUILD.gn` (libaperitif's install name), and `chrome/browser/web_applications/os_integration/mac/BUILD.gn` (app_mode_loader). The same patch names the engine's Keychain item "Pane Safe Storage" (ADR 0043).

The framework's exports are explicit. Chromium builds with hidden visibility, and the API the app links is marked `PANE_EXPORT` (`engine/pane/public/PaneExport.h`). Beside Chrome's own entry points, `chrome/app/framework.exports` lets `_OBJC_CLASS_$_Pane*`, `_OBJC_METACLASS_$_Pane*`, and `_Pane*` through, and nothing else names them. Until the review of 0.18.0 `chrome/app/framework.order` had to list every one, in order, since `verify_order.py` failed the build otherwise, which took a second build for each new class and 46 lines of patch to carry (`engine/scripts/update-exports.sh` wrote the list). Chrome's check that `_ChromeMain` is last only serves its startup paging, so patch 0001 turns it off in `chrome/BUILD.gn`, and `nm -jUng` shows the exports `framework.exports` lets through and no others. The app builds against the headers in `engine/pane/public/`, the `PaneCore` module.
