# The engine is Chrome's own framework and layer, Pane's by its branding, with explicit exports

The engine is Chrome's own framework, built from Chromium's `chrome/` layer with `//pane` linked in (ADR 0004), under Pane's name and brand. `pane/BRANDING`, which `branding_file_path` in `chromium/args/release.gn` points to, carries the Pane names and the identifier `xyz.roundedcorners.pane` (`MAC_BUNDLE_ID`; `com.pane.desktop` until 0.14.0, ADR 0114), after which Chromium names everything: the helpers, `Pane Helper (…)`; the framework, `Pane Framework.framework`; and its bundle, `xyz.roundedcorners.pane.framework`. It was `PaneCore.framework` until the review of 0.18.0, a name set in five of Chromium's files for no reason but the name (ADR 0004), and an update replaces the whole bundle. The name holds a space, which `app/project.yml` and `scripts` quote. `import PaneCore` stays, as it comes from `pane/public`, and so do the archives' `PaneCore-` names. The same patch names the engine's Keychain item "Pane Safe Storage" (ADR 0043).

The framework's exports are explicit. Chromium builds with hidden visibility, and the API the app links is marked `PANE_EXPORT` (`pane/public/PaneExport.h`). Beside Chrome's own entry points, `chrome/app/framework.exports` lets `_OBJC_CLASS_$_Pane*`, `_OBJC_METACLASS_$_Pane*`, and `_Pane*` through, and nothing else names them. Until the review of 0.18.0 `chrome/app/framework.order` had to list every one, in order, since `verify_order.py` failed the build otherwise, which took a second build for each new class and 46 lines of patch to carry (`scripts/update-exports.sh` wrote the list). Chrome's check that `_ChromeMain` is last only serves its startup paging, so patch 0001 turns it off in `chrome/BUILD.gn`, and `nm -jUng` shows the exports `framework.exports` lets through and no others. The app builds against the headers in `pane/public/`, the `PaneCore` module.
