# Extensions have their own page

Extensions are managed on a page of their own, out of Settings, at the user's request: every browser has one, Chrome's chrome://extensions and Aside's aside://extensions. The page takes the content panel as Settings does (`BrowserModel.Page.extensions`). Paper drew it first: 08 · Extensions, light and dark, with a search, no extensions, and Remove (ADR 0058).

Its header holds the puzzle, Extensions, the profile select, and Update all, and a search by name or description follows. Then come the cards, two to a row: a 40-point icon, the name and version, two lines of description, and the menu's pin; Options (when the extension has a page) and Remove; and the switch. A pinned extension shows the struck pin in blue, as the extensions menu does; Paper's boards, which had the two pins the other way round, now match. The profile select chooses whose extensions the page lists, since each profile has its own (ADR 0031). At the user's request it has no color bar: its border is in the profile's color at 40%, as the active profile's row in the sidebar had it then. Paper's six boards follow.

The page opens from the extensions menu's Manage all extensions, from the more menu's and the right-click menu's Manage Extension (at the extension's card), and from Window › Extensions. Window › Extensions has no key: ⇧⌘E is a page's (Docs centers text with it), and a menu's key would take it. Settings lost its Extensions section, and Security follows Memory & disk.

The page has no install field, at the user's request. Its first version kept the Electron app's install by Web Store URL or ID, with a link to the Web Store under it; both are gone, and `ExtensionInfo.webStoreID(from:)` went with them. Extensions come from the Web Store's own install button (Add to Chrome then, Add to Pane since ADR 0076), which the extensions menu's Visit Chrome Web Store and the page's empty state open. `extension-management` installs by ID through the automation channel, and `dark-reader` presses the store's own button.

A crash was fixed before the page shipped. The cards were rows of indexes into the list: removing an extension shrank the list before SwiftUI dropped the last row, which read past the end (`extension-management` and a check of its own caught it). Rows now carry their extensions. The scenario still allows accessibility's `-25204` on the popup's Remove, since the uninstall page's new tab can outlast the press.
