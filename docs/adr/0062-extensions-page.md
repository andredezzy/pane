# Extensions are managed on Chrome's own extensions page, in the profile's tab, and they update themselves

> **Rewritten on the Views line** (`docs/plans/views-migration.md`, X4 and X5, D3): this record held Pane's own Extensions page, its Details, and its Keyboard shortcuts dialog (ADR 0098), drawn in SwiftUI from 0.13 to 0.19. The user chose Chrome's own pages in their place (D3, Paper 10.1 to 10.3, approved 2026-11-08), and the record now holds that decision; what Pane's page was, and why it went, is under "Pane's page, until the Views line" at the end.

A profile's extensions are managed on Chrome's own page, `chrome://extensions`, in a tab of that profile, as every Chromium browser manages them: Chrome's list, an extension's Details (`chrome://extensions/?id=`), and its Keyboard shortcuts page (`chrome://extensions/shortcuts`, ADR 0098). D3 took them for Pane: about 1,000 Swift lines (`ExtensionsPage`, `ExtensionDetailsView`, `ExtensionShortcutsView`) and the engine code that copied Chrome's pages for them (`PaneExtensionDetails`, `PaneExtensionCommand`, `browser_context.mm`'s site access, file access, sites, and commands) went, and every function stays: search, Details, Site access with Add a site, the options page, Remove, on and off, Pin to toolbar, and the shortcuts. The page is Chrome's WebUI over the profile's hidden Browser (ADR 0014), which it needs nothing of Pane's to run on.

- **Where:** a tab of the profile, under Pane's toolbar, its address `chrome://extensions/`, and in the sidebar a tab named Extensions with Chrome's puzzle (Paper 10.1). The extensions menu's Manage all extensions, Window › Extensions (the active profile's), and an extension's Manage Extension and View Web Permissions open it in the profile's tab that shows the page already, at any of its places, and take it where they ask (the list, or the extension's Details); with none, in a new tab of the profile, as Chrome's `ShowSingletonTabOverwritingNTP` does with `IGNORE_AND_NAVIGATE` (`UiApp::OpenExtensionsTab`).
- **What it shows:** Chrome's own, as 10.1 to 10.3 draw it: the search, Developer mode (Load unpacked, Pack extension, Update, each card's ID and views to inspect), the left nav's My extensions, Keyboard shortcuts, and "Discover more extensions and themes on the Chrome Web Store", the link this record had taken off Pane's page; the cards in one column, Details and Remove, and the switch; Details' version, size, permissions, Site access with its sites and Add a site, Site settings, Pin to toolbar, Allow access to file URLs, Extension options, Open extension website, View in Chrome Web Store, the source, and Remove extension. Developer mode and the Web Store's link stay (the user's answer on 10.1). Its words are Chromium's ("Chromium" where Pane would name itself), and it follows the Theme as a page does (ADR 0001).
- **No profile select:** the page lists the extensions of the profile whose tab shows it; another profile's are in a tab of that profile (10.1's note). Deleting a profile takes its page with its tabs.
- **No Allow in Incognito:** Pane has no incognito, a profile being apart already. Each of Pane's profiles holds incognito off by Chrome's own pref (`IncognitoModePrefs::SetAvailability(kDisabled)`, in `ApplyProfileDefaults`), which the page reads (`developerPrivate.getProfileConfiguration`'s `isIncognitoAvailable`) to hide the row, as it does wherever incognito is off (`detail_view.ts`). A pref the profile holds, not a policy's: nothing on the page reads as managed. Chrome's other ways into an incognito window (an extension's `windows.create`, a link's menu item) stay shut with it. No Chromium file is changed for it.
- **Remove:** Pane's own Remove from Pane (the extensions menu's more menu, a pinned action's right-click menu) asks in Pane's popup (ADR 0056). The page's own Remove calls `chrome.management.uninstall` with its confirmation, which Chrome shows in its own dialog: Chromium has no seam for that dialog short of a patch (its `ExtensionUninstallDialog` is made in `extension_uninstall_dialog_impl.cc` and shown by `ShowDialog`, with no view factory), so it shows as Chrome draws it, for the user to decide in Paper.
- **The shortcuts page** is ADR 0098's.

**Extensions update themselves,** as in every browser, and the page has no Update all outside Developer mode. It was the user's call (2026-10-29): the button should not exist. Chrome's extension updater runs in Pane's engine as it is: as each profile starts, it asks Chrome's update service (`update.googleapis.com/service/update2/json`) for newer versions of its Web Store extensions, then again every five hours or so, and installs what it finds, as Chrome does. It is the one request Chrome makes of its own that Pane keeps, the exception to ADR 0040. A profile that is not open does not check; it checks when it next opens, as a Chrome profile does. Developer mode's Update, on Chrome's page, checks at once, as in Chrome.

The page opens as fast as its tab: from Manage all extensions to the frame that shows its tab, 5.8 ms to the compositor's commit and 14.1 ms to the screen, and on to the page's first paint, 62.7 ms and 71 ms, the WebUI's renderer started with it (medians of 6 and 5 runs on the M-series Mac the migration measures on, 2026-11-11, by the app's signposts "Open extensions page" and "Extensions page painted", the `views-extension-pages` rig). The Swift's page was never timed.

What was rejected:

- **Keeping Pane's page** (the plan's own recommendation): the user chose Chrome's (D3), so a page Pane copied from Chrome's no longer needs its engine code, and every function stays.
- **Allow in Incognito shown:** Pane has no incognito (the user's answer on 10.2).
- **Turning incognito off by policy:** the page would read as managed by an organization. **By a patch to the page:** ADR 0004 keeps Chromium's files as they are where a pref does it.
- **Routing the page's own Remove to Pane's popup** by registering Pane's own `management.uninstall` over Chrome's in the extension function registry: it would rewrite a security check of Chrome's for one dialog's look.
- **A profile select on the page:** Chrome's page lists its own profile's; a tab of each profile does what the select did.
- **Keeping a button for an update now, or checking more often than Chrome:** stable browsers have none in view, and the Web Store's servers expect Chrome's five hours.

How it is checked:

- **`extension-management`:** Manage all extensions opens `chrome://extensions` in the profile's tab, titled Extensions, and opens it again in that tab; an install declined at Pane's dialog leaves nothing on the page or on disk; one accepted lists there, on and pinned; the card's switch turns it off and on, Details' Pin to toolbar unpins and pins it, with no Allow in Incognito; Remove from Pane asks in Pane's popup and the page lists it no more. Chrome's page is pressed with real clicks on it (CDP's Input).
- **`extension-details`,** with a probe that asks for every site, downloads, and notifications, and has an options page and a homepage: Manage Extension opens its Details in the profile's tab (`?id=`), titled "Extensions - Pane details probe": < 1 MB, Unpacked extension, Display notifications and Manage your downloads, On all sites, Allow access to file URLs, its website, no Web Store page, and no Allow in Incognito. The pop-up, chosen with the keyboard as a person types its options' first letter (a click opens the system's menu, which no background run can choose in), goes On click (the probe loses every site) and On specific sites, which opens the page's Add a site: "not a site" is refused, example.com added, and the probe has it; the site's own menu removes it; the action menu's On All Sites gives every site back and Details follows; file access goes both ways; the back arrow shows the list; the card's Details and View Web Permissions open Details again, in the same tab.
- **`extensions-page-profile`:** the probe, on in Alpha and off in Bravo, reads so on each profile's own page; deleting Bravo leaves Alpha's page as it was.
- **`extensions-menu`, `extension-context-menus`, `navigation`:** Manage all extensions and Manage Extension open the page and Details in the same tab; the action menu's On <site> joins Details' list; the page behind the extensions page's tab is hidden until its tab is selected again.
- **`extension-auto-update`:** Dark Reader installed from the Web Store, then a relaunch with a network log: once the profile opens, Pane asks the update service by itself, naming Dark Reader (`X-Goog-Update-AppId`).
- **On screen:** `views-extension-pages` captures the list, Details, and the shortcuts page in the profile's tab, light and dark, against 10.1 to 10.3, and what the page's own Remove shows.

Pane's page, until the Views line (0.13 to 0.19): extensions were managed on a page of Pane's, out of Settings, at the user's request (every browser has one; Chrome's chrome://extensions and Aside's aside://extensions), drawn in Paper first (09 · Extensions). It took the content panel as Settings does; its header held the puzzle and the title, Keyboard shortcuts (ADR 0098), and the profile select, whose border took the profile's color at 40%; a search, then cards two to a row with the menu's pin, Details, Options, Remove, and the switch. Details was a view inside the page, 640 points at most, in Settings' layout (ADR 0065): the header with the version, size, and source on one line, the description, the permissions in Chrome's words, Site access with its sites in the form a person writes them (example.com, not \*://example.com/\*) and Pane's own Add a site dialog, Pin to toolbar, Allow access to file URLs, the links, and Remove. The engine made Details' data as Chrome's `ExtensionInfoGenerator` makes the details page's, set site access as `developerPrivate` does, and took sites through the page's own pattern; PaneKit's `ExtensionSite` wrote them. Its install field by Web Store URL or ID, and an Update all button, had gone at the user's request before the page shipped. Its rows once indexed the list and read past its end as one was removed; they carried their extensions after that. All of it went at X4: Chrome's page does each of these things itself.
