# Saves run off the main thread and write only what changed

> **Partly replaced by [ADR 0113](0113-profile-data-encrypted-under-a-key-the-pin-releases.md)** — the proxy passwords are no longer written apart: they are in `profiles.json`, which is sealed under the data key as it is written.

The app saves its state off the main thread, Chromium's UI thread, and writes only the file whose state changed, so a page's title, URL, or favicon changing costs the UI thread a copy, not an encode and a write. `model::BrowserModel` (`pane/model/browser_model.h`) waits 300 ms after the last change (`kSaveDelay`), then hands a copy of what changed to `ModelStore` (`pane/model/model_store.h`), which encodes, seals (ADR 0113), and writes each file through its `ImportantFileWriter` on a sequence of its own, in the order asked: the JSON, AES-GCM, and base64 never run on the UI thread, where Views composites. Tabs never rewrite `settings.json`, and a first launch that changes no setting writes none. `SaveNow` hands over what changed at once: at quit, which waits for the write (ADR 0016), as Pane locks (ADR 0116), and for scenarios that read the files. A failed write marks its file changed again, so the next save retries.

A favicon is stored at most 32 pixels a side, the 16 points it draws at, at 2×, as a PNG data URL encoded off the UI thread, only the latest of a burst (`pane/ui/tabs/favicons.cc`, ADR 0072).

A file that does not open or decode is kept aside (`profiles.json.damaged`, `settings.json.damaged`) before the first save writes over it, as `security.json` is (ADR 0042). The proxy passwords were written on the same sequence, before the file (ADR 0037); they are now in `profiles.json`, sealed with it (ADR 0113).

Every such change used to encode every profile, tab, and favicon, then write `profiles.json` and `settings.json`, on the main thread, 300 ms later. Measured in the Swift app's model with 300 tabs in 6 profiles, a save held the main thread 21.7 ms with 360-pixel favicons (47 KB of base64 each, a 14 MB file); the copy that replaced it took 0.006 ms, and the same tabs with 32-pixel favicons wrote 1.4 MB in 2.5 ms, off the main thread. The Swift app still encoded each favicon update on its main thread. `restore` checks that saving tabs leaves `settings.json` unwritten; before, the first save wrote it.
