# Extensions ask in popups, and adding one asks in Dia's dialog

Pane asks about an extension in its own views, Aside's popup to remove one and Dia's dialog to add one, never in an AppKit sheet, because a sheet takes some 280 ms to show and holds the main thread while it does. The user reported a visible delay between the Web Store's Add to Chrome (Add to Pane since ADR 0076) and the confirmation, then named Aside's popups as the model; they were designed in Paper first (`03 · Components` › 03.10 Browser · Extension popups).

The cause was the sheet. Measured from the store page's own button, the engine asked the app 50 ms after the click (229 ms on the first), and the `NSAlert` sheet took the rest: it showed at alpha 0 after 32 ms, reached full alpha at 162 ms, and settled at 240 ms, while `beginSheetModal` held the main thread, Chromium's UI thread, for 286 ms. Any sheet costs that on this macOS, even an empty `NSPanel`, and neither `animationBehavior = .none` nor a shorter `animationResizeTime` or `NSWindowResizeTime` changes it.

Removing asks in the popup (`ExtensionPromptView`), 320 points wide under the extension's toolbar button, or the puzzle while it has none, and centered where no toolbar shows. The icon sits beside the title, then Report abuse, which, ticked, opens the Web Store's report page as Chrome's dialog does, then Cancel and Remove. Return accepts; Esc or a click outside cancels. It is in the view tree 3 to 4 ms after the request, and the main thread stays free. The Extensions page's Remove, the more menu, and a pinned action's right-click all ask there. The confirm dialog that had asked before an uninstall (`ConfirmDialogView`) went, with `WindowState.dialog` and its scrim, once nothing showed it.

Adding asks in Dia's dialog (the user's model), measured at 2× from the user's screenshot and drawn in Paper first (03.10, and 04.10 Install extension). `ExtensionInstallDialog` is centered on Quit Pane?'s scrim, 424 points wide: Pane's icon, an arrow, and the extension's, at 32 points; "Add “Name” to Pane?" at 20 points, semibold; what the extension can do, on a panel of the foreground at 4%; then Cancel with Esc and Add to Pane with ↩, on Quit Pane?'s keyed buttons, which gained a primary role for it (ADR 0053). Chrome's other prompts there (new permissions, re-enabling) keep their own titles (PaneKit's `ExtensionPromptText`).

What stays slow is the engine's first click, 168 to 229 ms, which Chrome shares: Chromium decodes the store's manifest and icon in isolated utility processes. A page's own requests kept their sheets, at the same cost, until they too were drawn in the window (ADR 0080). The `extensions-menu` scenario presses the more menu's rows and answers both prompts, and `extension-management` removes through the popup.
