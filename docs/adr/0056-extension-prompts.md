# Extensions ask in popups, and adding one asks in Dia's dialog

Pane asks about an extension in its own views, Aside's popup to remove one and Dia's dialog to add one, never in an AppKit sheet, which holds the main thread some 280 ms as it attaches (ADR 0021). The user reported a visible delay between the Web Store's Add to Chrome (Add to Pane since ADR 0076) and the confirmation, then named Aside's popups as the model; they were designed in Paper first (`03 · Components` › 03.10 Browser · Extension popups).

The cause was the sheet. Measured from the store page's own button, the engine asked the app 50 ms after the click (229 ms on the first), and the `NSAlert` sheet took the rest: it showed at alpha 0 after 32 ms, reached full alpha at 162 ms, and settled at 240 ms, while `beginSheetModal` held the main thread for 286 ms.

Both prompts are `pane/ui/dialogs/extension_prompt_view`, shown at once by the window's extensions (`ExtensionsUi::Ask`), with what `pane/model/extension_text` makes them say:

- **Removing asks in Aside's popup**, 320 points wide under the extension's pinned button, else the puzzle, on the popovers' surface: the icon beside the title, then Report abuse, on the system's own checkbox (`pane/ui/design/checkbox`), which, ticked, opens the Web Store's report page as Chrome's dialog does, then Cancel and Remove. The extensions menu's more menu and a pinned action's right-click menu ask there, through Remove from Pane (ADR 0054). Chrome's own extensions page's Remove keeps Chrome's dialog (ADR 0062).
- **Adding asks in Dia's dialog** (the user's model), measured at 2× from the user's screenshot and drawn in Paper first (03.10, and 04.10 Install extension), on the modal scrim, 424 points wide: Pane's icon as the Dock shows it, an arrow, and the extension's, at 32 points; "Add “Name” to Pane?" at 20 points, semibold; what the extension can do, on a panel of the foreground at 4%; then Cancel with Esc and Add to Pane with ↩, on Quit Pane?'s keyed buttons, which gained a primary role for it (ADR 0053). Chrome's other prompts there (new permissions, re-enabling) keep their own titles. It comes straight from Chrome's install hook, patch 0005's, for Pane's profiles alone (`AskToAddExtension`, `pane/ui/dialogs/add_extension.h`): Chromium has no view factory for that dialog.

Each holds the keys while it asks: Return accepts and Esc cancels from whatever has the keys (`RootView::OverlayKey`, ADR 0079), a shortcut still runs, and the rest goes nowhere. A press outside it cancels, and the Lock answers it no (ADR 0042). Each shows in the frame after it is asked for: adding, 8.8 ms from Chrome's hook to the compositor's commit and 13.6 ms to the screen; removing, 5.7 ms and 13.3 ms from Remove from Pane (medians of 6 and 12 runs, `tests/rigs/views-extension-pages.ts`). The Swift app's popup was in its view tree 3 to 4 ms after the request, a frame not timed; the confirm dialog that had asked before an uninstall before it (`ConfirmDialogView`) went once nothing showed it.

What stays slow is the engine's first click, 168 to 229 ms, which Chrome shares: Chromium decodes the store's manifest and icon in isolated utility processes. The `extensions-menu` scenario presses the more menu's rows and answers both prompts, and `extension-management` removes through the popup.
