# Extensions ask in popups, and adding one asks in Dia's dialog

> **On the Views line** (`docs/plans/views-migration.md`, X3): both prompts are Views (`pane/ui/dialogs/extension_prompt_view`), shown at once, as the Swift's were, by the window's extensions (`ExtensionsUi::Ask`): adding, Dia's dialog on the modal scrim, straight from Chrome's hook (`AskToAddExtension`) for Pane's profiles; removing, Aside's popup under the extension's pinned button, else the puzzle, from the menus' Remove from Pane, Report abuse on the system's own checkbox (AppKit's cell, `pane/ui/design/checkbox`). Each holds the keys while it asks (Esc cancels, Return accepts, a shortcut still runs, the rest goes nowhere), a press outside it cancels, and the Lock answers it no. Chrome's extensions page's own Remove asks in Chrome's dialog (ADR 0062). Each shows in the frame after it is asked for: adding, 8.8 ms from Chrome's hook to the compositor's commit and 13.6 ms to the screen; removing, 5.7 ms and 13.3 ms from Remove from Pane (medians of 6 and 12 runs, the `views-extension-pages` rig), where the Swift's popup was in its view tree 3 to 4 ms after the request, a frame not timed.

Pane asks about an extension in its own views, Aside's popup to remove one and Dia's dialog to add one, never in an AppKit sheet, which holds the main thread some 280 ms as it attaches (ADR 0021). The user reported a visible delay between the Web Store's Add to Chrome (Add to Pane since ADR 0076) and the confirmation, then named Aside's popups as the model; they were designed in Paper first (`03 · Components` › 03.10 Browser · Extension popups).

The cause was the sheet. Measured from the store page's own button, the engine asked the app 50 ms after the click (229 ms on the first), and the `NSAlert` sheet took the rest: it showed at alpha 0 after 32 ms, reached full alpha at 162 ms, and settled at 240 ms, while `beginSheetModal` held the main thread for 286 ms.

Removing asks in the popup (`ExtensionPromptView`), 320 points wide under the extension's toolbar button, or the puzzle while it has none, and centered where no toolbar shows. The icon sits beside the title, then Report abuse, which, ticked, opens the Web Store's report page as Chrome's dialog does, then Cancel and Remove. Return accepts; Esc or a click outside cancels. It is in the view tree 3 to 4 ms after the request, and the main thread stays free. The Extensions page's Remove, the more menu, and a pinned action's right-click all ask there. The confirm dialog that had asked before an uninstall (`ConfirmDialogView`) went, with `WindowState.dialog` and its scrim, once nothing showed it.

Adding asks in Dia's dialog (the user's model), measured at 2× from the user's screenshot and drawn in Paper first (03.10, and 04.10 Install extension). `ExtensionInstallDialog` is centered on Quit Pane?'s scrim, 424 points wide: Pane's icon, an arrow, and the extension's, at 32 points; "Add “Name” to Pane?" at 20 points, semibold; what the extension can do, on a panel of the foreground at 4%; then Cancel with Esc and Add to Pane with ↩, on Quit Pane?'s keyed buttons, which gained a primary role for it (ADR 0053). Chrome's other prompts there (new permissions, re-enabling) keep their own titles (PaneKit's `ExtensionPromptText`).

What stays slow is the engine's first click, 168 to 229 ms, which Chrome shares: Chromium decodes the store's manifest and icon in isolated utility processes. The `extensions-menu` scenario presses the more menu's rows and answers both prompts, and `extension-management` removes through the popup.
