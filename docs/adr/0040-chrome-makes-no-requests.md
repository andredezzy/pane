# Chrome makes no request of its own

> **Corrected by [ADR 0111](0111-chromes-crlset-ships-with-the-app.md)**: "CRLSets … update with the app" held only for the root store, since no CRLSet shipped and the engine used Chromium's empty built-in one. Each build now carries Chrome's.

Every request Chrome made on its own, outside the pages, is off: some carried a profile's Google cookies, some went out from the browser itself, past every profile's proxy, with the Mac's real address, and the Electron app made none. They first showed with the per-profile proxy (ADR 0037): Chrome's own background requests to `accounts.google.com` and `www.google.com` went out per profile, through its proxy, where the Electron app made none, and whether to turn them off went to the fingerprint work, which owns what a profile reveals (ADR 0038). A net log of a quiet session then named each source by its traffic annotation.

The component updater (`update_client`) is off with `--disable-component-update`. The on-device AI model's manifest registered itself on demand regardless; patch `engine/patches/0007-pane-quiet.patch` makes it honor the switch. The network time check (`network_time_component`) is off with the `NetworkTimeServiceQuerying` feature. AI Mode's eligibility check (`aim_eligibility_fetch`), which carried a profile's Google cookies and country, is off with the `Aim*` features. The Translate ranker model (`ranker_url_fetcher`) is off with the `TranslateRanker*` features, and Translate itself is off per profile (`translate.enabled`). The Google account list (`gaia_auth_list_accounts`) sent a profile's Google cookies on every launch, from sign-in metrics among other callers: patch 0007 makes `TriggerListAccounts` do nothing when Pane hosts the engine (ADR 0010), and browser sign-in is off per profile (`signin.allowed`). Signing in to Google's websites is unaffected, as the `google` and `extension-management` scenarios show. The switch and the features are set in `engine/pane/browser/browser_application.mm`, the per-profile prefs in `engine/pane/browser/browser_context.mm`.

The component updater, the network time check, and the on-device AI model were the requests that went out from the browser itself. Pane gives up Chrome's component updates, as the Electron app never had them: CRLSets and the Chrome Root Store update with the app instead. The `quiet` scenario keeps every source off: a quiet session reaches nothing but its local fixtures.
