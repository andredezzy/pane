# Deleting a profile is durable before it completes, and asks no page

> **Refined by [ADR 0113](0113-profile-data-encrypted-under-a-key-the-pin-releases.md)** — a delete cut short is finished when the data volume next opens, no longer before the engine starts — **and by [ADR 0116](0116-pane-locks-while-open.md)**: a lock waits for a delete under way, and its folder goes at the next open.

A profile's delete completes only once Chrome has marked the profile for deletion, it is recorded on disk until then, and no page of the profile can hold it back, so a quit, a crash, or a page never leaves a deleted profile's data behind. Delete profile asks first with the system's alert, a sheet on the window: Delete “<name>”?, with Cancel and a destructive Delete (`ShowSystemAlert`, `pane/ui/dialogs/system_alert_mac.mm`).

**The engine's sequence** is `pane::DeleteProfile` (`pane/browser/profiles.cc`), from `ProfileContexts::Delete`, which opens a profile not open this session first, so the engine data of earlier sessions goes too. It completes from `ProfileManagerObserver::OnProfileMarkedForPermanentDeletion`, not when the request is made: Chrome first closes the profile's browsers, asynchronously, and a quit before that point used to leave the profile and its data in place. Chrome then removes the profile's link under `Engine/`, and Pane its folder in the data volume (`DataVault::Remove`).

**The record.** The app removes the profile from its model at once and lists it in `deletions.json` (`pane/model/profile_deletions`) until the engine confirms. The record is written on the vault's volume sequence (`DataVault::RecordDeletion`), where the open's purge reads and writes it too, so the two never race, and it is on disk before the engine's data starts going. A delete cut short by a quit, a crash, a lock, or a context that would not open is finished at the next open of the data volume, a launch's or an unlock's, once it is mounted and before any profile opens: `ProfileDeletions::Purge` removes the profile's links (ADR 0006), any plain folder an earlier Pane left, and its folder in the volume. An id that is not one folder name is dropped, never followed. The panic wipe erases the file with the rest (ADR 0042).

**Deleting asks no page.** Chrome's deletion closes the profile's Browsers with beforeunload, and a page answering "Stay" cancelled it, left the profile loaded with no context, and withheld the completion until quit. `DeleteProfile` closes every page of the profile, in every window, without beforeunload, before Chrome's sequence. `profile-lifecycle` arms a page with beforeunload before deleting its profile, and checks that nothing asked and the engine confirmed.

**A context that will not open fails its callers.** Its failure had dropped the waiters with a log line: the selected tab had no page and no sad tab, and a deleted profile stayed "deleting" with its engine data on disk. `ProfileContexts::With` hands its callers null. The tab shows the sad tab, whose Reload selects it again and so retries the open; a tab opened in the background is marked the same; and the delete stops waiting, leaving its folder to the next open. The same work found that an open never answered for a 300-character id (too long a path). Profile ids are UUIDs, so nothing reached it, and the engine answers every open (ADR 0017).

Until 0.20.0 the Swift app asked the engine through its Objective-C API (`deleteContext:completion:`, `openContext`), and kept `deletions.json` through PaneKit's `ProfileDeletions`; the sequence moved into `//pane` unchanged.

How it is checked: `profile-lifecycle` deletes a profile and its data; deletes one whose page has beforeunload, unasked; opens profiles the engine refuses (an id with a slash, and one too long to be a folder), whose tabs show the sad tab and whose deletes leave nothing pending; finishes, at a relaunch, a delete that `deletions.json` still lists; and finishes one whose folder a kill interrupted. `pane_unittests` checks the record's purge (`ProfileDeletionsTest.Purge`) and that an id that isn't one folder is refused before anything is removed (`DataVolumeTest.OutsideItsFolders`).
