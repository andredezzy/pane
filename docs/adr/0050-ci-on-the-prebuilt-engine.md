# CI builds the app on the prebuilt engine and never builds Chromium

CI builds and packages the app on the prebuilt engine its engine sources name (ADR 0049) and never builds Chromium, which takes hours and some 100 GB; engine builds stay on a developer's Mac. The App workflow (`.github/workflows/app.yml`) runs PaneKit's tests, takes the engine key, fetches the engine by it (cached by key), and runs `engine/scripts/package.sh`, on pushes to `main` and pull requests that touch `app/`, `engine/`, `third_party/`, or the workflow and its setup. The Release workflow (`release.yml`) builds the dmg the same way (ADR 0051). Both share one composite action, `.github/actions/setup-app-build`, which installs XcodeGen and fetches the engine.

The runner is GitHub's `xcode-27` image (macOS 27 and Xcode 27, in preview), the toolchain the app is built with. `macos-26` would default to Xcode 26.6, which the app has never been built with. actionlint does not know the preview label yet, so `.github/actionlint.yaml` names it; if GitHub renames the label when the image leaves preview, both change (`docs/human-checklist.md`).

What CI runs is pinned. XcodeGen is its 2.46.0 release zip, checked by SHA-256 as `dist.sh` checks dmgbuild, so two builds of one tag generate the same project; it had been Homebrew's latest. Every action is pinned by commit, its version beside it. Only a tag on `main` publishes: `release.yml` fetches the whole history and refuses a tag whose commit is not on `main`, since every Pane's update check offers the latest release at once.

A missing engine fails its own step. `main`'s first native run failed on a missing PaneCore, its reason far up the log: the setup action wrote `fetch-engine.sh`'s output within `echo`'s arguments, so an unpublished engine left the fetch green and `PANE_ENGINE_OUT` empty. The fetch now fails its own step, and its message names the `engine-<key:12>` prerelease to publish and the script that publishes it.

The repo's other gates run in `gates.yml`, on a Linux runner: ESLint, Biome (`ci`), the scenario runner's typecheck, and knip, on pushes to `main` and every pull request. Biome checks every tracked file, so no paths filter fits it. Electron's binary is not downloaded, since no gate runs the migration scenario.

Before they ran on GitHub, the workflows were checked locally. actionlint 1.7.9 with shellcheck passes. Every step of the app's passed in a fresh clone with no Chromium checkout, on an engine served from a local folder laid out as GitHub serves release assets. The new `run:` steps ran with GitHub's env files emulated: the XcodeGen install with the right and a wrong SHA-256, and the main check on `main`'s commit and on that of `native-shell`, the native app's branch then. On GitHub, `main`'s first green run took 3 min 37 s.
