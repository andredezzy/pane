# Theme drives the app and every page

The theme setting (`system` / `light` / `dark`) is Chromium's app-level color scheme (`ui::NativeTheme`'s override, `pane/ui/design/theme.cc`), so one knob drives Pane's chrome, the native menus it opens, AND the `prefers-color-scheme` every website in every profile observes — the same coupling desktop Chrome's appearance setting has. Each window's colors follow it, and so does its NSWindow's appearance, which the menus it opens take. Settings' Theme menu sets it; a change spends about 7 ms in Chromium's color machinery before its frame (every color provider destroyed and built again with Chrome's mixers, and each page's color maps). The Electron app made the same choice through `nativeTheme.themeSource`, and the Swift app through `NSApp.appearance`, which Chromium's native theme followed: neither could split them either.

We first considered theming only Pane's chrome and leaving websites on the real OS scheme (arguably "honest" for fingerprinting), but rejected it because native context menus would then mismatch the chrome whenever the theme differs from the OS — and since real Chrome exposes its appearance setting to websites the same way, following it is Chrome parity, not a fingerprint anomaly.
