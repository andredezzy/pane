# The Chromium checkout is a shallow clone of the tag, kept out of Spotlight

The Chromium checkout is a shallow git clone of the pinned tag (ADR 0005) with an unmanaged `.gclient`, synced with `--no-history --shallow`, rather than the official source tarball, which is Linux-oriented and skips Mac-only deps and hooks. `engine/scripts/sync.sh` makes it at `~/chromium` (`CHROMIUM_ROOT` overrides it), outside the repo. It clones `depot_tools`, writes the `.gclient` (unmanaged, so gclient syncs DEPS but never moves `src` off the tag), clones `src` at the tag with depth 1, syncs the deps, runs the hooks, and links `src/pane` to `engine/pane`. Moving to another tag fetches that tag alone, so the checkout stays shallow. A step already done is skipped: a second run on a synced checkout changes nothing.

The checkout is kept out of Spotlight, and the build leaves the system headroom, because the first engine build kernel-panicked the Mac (2026-10-26, 01:41 local): `watchdog timeout: no checkins from watchdogd in 93 seconds`, the panicking thread a `clang` from the build. The build ran about 18 compile jobs while Spotlight (`mds`) indexed the fresh 500k-file checkout, and a jetsam event 40 minutes earlier showed memory pressure during the dependency sync. So the checkout lives in `~/chromium.noindex` (Spotlight skips `.noindex` directories), and `~/chromium` is a symlink to it, so every path in the scripts still works; Chromium's own Mac build docs recommend keeping the checkout out of Spotlight. And `engine/scripts/build.sh` runs a third of the cores' compile jobs (6 of the 18 here) under `nice`. A utility-QoS clamp was tried first and dropped: it cut throughput about 5× (≈80 against ≈430 Siso steps a minute, a build of about 9 hours), while a cap of two thirds (12 of the 18) alone held the load near 19 with memory 86% free. That cap lasted until 2026-10-30, when it reset the Mac again by watchdog (`wdog,reset_in_1`), three minutes into a patch release's build (157.0.8103.26, ADR 0005) while the Mac was in use. `PANE_BUILD_JOBS=12` is for an idle Mac. `engine/UPGRADING.md` asks for one Chromium build at a time.

The first build also set two prerequisites. ANGLE's Metal shaders need `xcrun metal`, which Xcode 27 does not install by default: the Metal toolchain is a separate component, installed with `xcodebuild -downloadComponent MetalToolchain` (no admin rights needed), and `docs/building.md` lists it beside full Xcode, an APFS volume, and about 100 GB free. And `enable_nacl` left the gn args (`engine/args/release.gn`): Chromium 156 no longer declares it (NaCl is gone), and gn warned the arg had no effect.

The checkout syncs for Windows too, since the UI's move to Views (`docs/plans/views-migration.md`, B4) compiles `//pane` for Windows from this Mac: `.gclient` names `target_os = ["mac", "win"]`, and a change to it removes the sync's markers, so the next `sync.sh` syncs again (with `-D`) rather than skipping a synced version. Windows' toolchain is Microsoft's files, packaged with `package_from_installed.py` from a Visual Studio install in the Windows VM and kept outside the repo, since they aren't Pane's to publish: `PANE_WIN_TOOLCHAIN_DIR` names the folder holding its `<hash>.zip`, and `sync.sh` points depot_tools at it (`DEPOT_TOOLS_WIN_TOOLCHAIN_BASE_URL`, and `GYP_MSVS_HASH_<TOOLCHAIN_HASH>` from `build/vs_toolchain.py`). Without it the toolchain's hook does nothing (`DEPOT_TOOLS_WIN_TOOLCHAIN=0`). `checkout_pgo_profiles` fetches Chrome's PGO profiles for the branch, which a `chrome_pgo_phase = 2` build reads. The first such sync, on 158, took about 20 minutes, with the toolchain's 8.5 GB unpacked into `src/third_party/depot_tools/win_toolchain`.
