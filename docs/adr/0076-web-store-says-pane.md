# The Chrome Web Store's buttons say Pane

On the Chrome Web Store, an item's install and remove buttons say Pane where the store says Chrome, at the user's request: "Add to Pane", "Remove from Pane", and the same in the store's other languages ("Ajouter à Pane", "Pane に追加", "Usar no Pane", "Supprimer de Pane"). French says Google Chrome, which becomes Pane too; German and Russian name no browser.

The store renders that text itself, client-side, so the engine renames it in the page (`engine/pane/browser/web_store.cc`). As each store document commits (`chromewebstore.google.com`, the main frame), the engine runs a script in Chrome's internal isolated world, which shares the store's DOM and none of its scripts. The script finds the item's install and remove buttons by the names the store gives them (jsname `wQO0od` and `ajZLRd`, the buttons its install controller routes clicks to, which the server-rendered markup names in that controller's jsaction), renames Chrome in their text and labels, and keeps renaming with a MutationObserver as the store redraws them: on install, or for another item reached without a page load. Its callbacks run before the next frame. In every load (7 in the scenario), the script ran before the page's first contentful paint and before the parser reached the button.

Four other ways were rejected. Renaming every button that names Chrome would also rename "Try Chrome Enterprise Core" and the store's "Install Chrome". A table of the store's labels needs its 50-odd languages, and the remove label exists only once rendered. Waiting for DOMContentLoaded could let the server-rendered "Add to Chrome" paint first. A component extension's content script is barred from the store.

`web-store-labels` checks it on the live store: English, French, Japanese, and Portuguese; another item reached the store's own way, in the same document; "Remove from Pane" after an install; every other button unchanged; and the store's markup on another site left alone. If Google renames those buttons, the label falls back to the store's own, and this scenario fails. The scenarios' extension helpers (`tests/lib/extensions.ts`) press "Add to Pane".

The store still tells Pane's users to switch to Chrome, with a "Switch to Chrome?" card and a banner: it does not take Pane for Chrome. That was seen and left as it is; installing works regardless.
