# Popups become tabs in the opener's profile

Pane has no popup windows: a page's popup opens as a tab in the opener's profile, inserted right after the opener, as the Electron app did with `setWindowOpenHandler`. `HostedWebContentsDelegate` (`pane/browser/ui/web_contents_delegate.cc`) turns window dispositions (`kNewPopup`, `kNewWindow`) into `kNewForegroundTab`, and the controller, which hears the window's Browsers itself (`WindowHost::Delegate`, `UiApp::TabInserted`), puts the new tab right after its opener and, when it is to show at once, selects it on the next turn (ADR 0017). `popup-new-tab` checks that pages that open windows get tabs instead, in their own profile, right after the opener.

Windows Chrome opens itself follow the same rule. `chrome.windows.create` opens a tab in the extension's profile, as the Electron app did. Chrome builds its new `Browser`, and `ForwardToPaneWindow` (`pane/browser/ui/window_host.cc`) folds it into the profile's hidden Browser in the Pane window (ADR 0014): a task later it moves the tabs there and closes the emptied Browser. `chrome.tabs.update({active: true})` selects the tab in the app, which follows Chrome's pick on the next turn, except for Chrome's pick as a tab closes, where the app picks the next tab itself. `tabs-api` checks both.
