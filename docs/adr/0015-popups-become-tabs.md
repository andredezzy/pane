# Popups become tabs in the opener's profile

> **On the Views line** (`docs/plans/views-migration.md`, H5): the controller hears the window's Browsers itself (`WindowHost::Delegate`, `UiApp::TabInserted`): a page's tab goes right after its opener, in the opener's profile, one to show at once selected on the next turn, and Chrome's own pick followed the same way; Chrome's windows still fold into the profile's Browser (`ForwardToPaneWindow`). `popup-new-tab` passes, and `tabs-api` with its extension popup's parts waiting for X2.

Pane has no popup windows: a page's popup opens as a tab in the opener's profile, inserted right after the opener, as the Electron app did with `setWindowOpenHandler`. `HostedWebContentsDelegate` (`pane/browser/ui/web_contents_delegate.mm`) rewrites window dispositions (`NEW_POPUP`, `NEW_WINDOW`) to `NEW_FOREGROUND_TAB`, and the app inserts the new tab after the tab it came from (`browserWindow:didInsertTab:opener:foreground:`). `popup-new-tab` checks that pages that open windows get tabs instead, in their own profile, right after the opener.

Windows Chrome opens itself follow the same rule. `chrome.windows.create` opens a tab in the extension's profile, as the Electron app did. Chrome builds its new `Browser`, and `ForwardToPaneWindow` (`pane/browser/ui/window_host.mm`) folds it into the profile's hidden Browser in the Pane window (ADR 0014): a task later it moves the tabs there and closes the emptied Browser. `chrome.tabs.update({active: true})` selects the tab in the app, which follows `browserWindow:didActivateTab:`, except for Chrome's pick as a tab closes, where the app picks the next tab itself. `tabs-api` checks both.
