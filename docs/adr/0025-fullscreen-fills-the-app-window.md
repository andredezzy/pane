# Fullscreen fills the app's window, and the window follows the page

A page's fullscreen fills the app's window, the root view laying it out with no sidebar, toolbar, or corners, and the window's own full screen follows the page's, as Chrome's does: it enters with the page and leaves with it, through `Widget::SetFullscreen` (`pane/ui/window/window.cc`). Chrome's "Press Esc" bubble is replaced by the app's hint, a view of Pane's (`pane/ui/page/exclusive_access_hint`), shown from `WindowHost::Delegate::ShowExclusiveAccessHint`: what Chrome's bubble would say, at 13 medium, white on a capsule of black at 75%, 24 from the window's top, faded 3.5 s after it shows, and gone with the fullscreen. Esc leaves fullscreen wherever focus is (ADR 0079). View › Enter Full Screen (⌃⌘F) toggles the window's full screen (`Window::ToggleFullScreen`), its title reading Exit Full Screen there, from the same command table as the keys (ADR 0019).

Following the page has one trap, found while checking the traffic lights through full screen (ADR 0036). The app had toggled the window whenever the page's fullscreen changed, and AppKit ignores a toggle while the window is still moving in or out: Esc pressed as the window entered, 354 ms after the page's request in the run that found it, left the page windowed and the window in full screen, the sidebar and toolbar back, for good. Chromium's own fullscreen controller, behind `Widget::SetFullscreen`, takes a request made while the window is still moving once the move ends, which the Swift app did itself (`FullScreenFollower`, a turn of the run loop after the move's end, since a toggle from within it is ignored too).

Two more rules came with it. The user's own full screen stays when a page leaves its fullscreen in it, as in Chrome, where the app had toggled it off. And leaving full screen (View › Exit Full Screen, or the green button) takes the page out of its fullscreen, which had stayed, filling a window with no sidebar or toolbar.

**On Windows Esc left the page in its fullscreen** (W4, 2026-11-13): Chrome's fullscreen controller lets the tab go itself only on the Mac, where a window reports its change at once (`FullscreenController::ExitFullscreenModeInternal`); elsewhere it asks the window to leave and waits for it to say so (`WindowFullscreenStateChanged`), as `BrowserView` and `WebUIBrowserWindow` do once their widget has left. Pane's window never said so, so the controller kept the tab, and took every Esc after it, the page never hearing one. Once the controller has asked, Pane's window says it has left the page's fullscreen (`HostedBrowserWindow::ExitFullscreen`, a turn later, `IsFullscreen` false for that call), the controller lets the tab go, and the window follows the page out as on the Mac. On Windows View › Enter Full Screen is F11 (ADR 0019). **And leaving the user's full screen there left the page in its fullscreen**, in a window out of it: Windows tells a widget's observers of a full screen entered or left only through a change of size read against the show state the widget saved, which a Show of a window already in full screen resets (`Widget::Show`: a reopen, a Browser's own Show, the channel's activate), so the window's leaving went unheard (`Window::OnWidgetShowStateChanged`). Windows' frame tells the widget of each change of full screen itself (`pane/ui/window/frame_win.cc`), as Views' own Linux host tells its window's.

On Windows `fullscreen` passes in the test VM in front (2026-11-13), the window's controls deferred to Paper's caption buttons (W5), the user's full screen taken by F11 there, where there is no menu bar.

The `fullscreen` scenario, where the run lets Pane take the front (ADR 0012), presses Esc as soon as the window starts entering, and the window then leaves full screen. It then takes a page into fullscreen inside the user's full screen, where Esc keeps the user's, and leaves full screen, which ends the page's fullscreen. Each time the traffic lights end at (12, 12); the build before the fix left the window in full screen, with the lights at AppKit's (9, 9). It passed on the Views build in front, light and dark, on 2026-11-12.
