# Extensions run on Chrome's extension system, per profile

Extensions run on Chrome's own extension system, so every extension API is Chrome's (ADR 0004), and each profile has its own: a profile is its own Chrome profile (`Engine/<id>`, ADR 0006), with its own extension registry, toolbar, and `Extensions/` folder, and the app keeps each profile's list by its id. The engine hands the app their toolbar actions, popups, install prompts, and management (`engine/pane/public/PaneExtensions.h`, `engine/pane/browser/extensions/`), and the app draws them (ADRs 0032, 0054, 0056, 0062).

Install prompts come from Chrome's `ExtensionInstallPrompt` (`engine/patches/0005-pane-extensions.patch`), and the app shows them as its own (ADR 0056); Ardia's `chromium-extension-install-prompt-hook` was evaluated and adapted that way. Ardia's hidden-window hooks (`chromium-hidden-window-current-window`, `chromium-extension-window-hidden`) are not needed: each profile's tabs live in a hidden `Browser` of Pane's window (ADR 0014), which Chrome already counts as the current window for popups and service workers.

The Electron app's extensions do not come over with the migration (ADR 0043). NordPass showed first what they carried: its Continue froze in a migrated profile and works on a fresh install, where it took a test address to Nord Account's sign-up page, so the freeze comes from the extension data the migration copied. Electron lacked APIs NordPass uses (`contextMenus`, `privacy`, `webNavigation`; its login page renders blank there), so that data is from a half-working extension. Reinstalling NordPass in that profile clears it; the vault itself is on NordPass's servers. Then the user reported an extension installed in one profile showing in several others. The engine was not sharing them. The Electron app had installed each extension once and loaded it into every profile, so the migration listed it as pending in all of them (`migration.json`), and each profile installed it as it opened, with Chrome's prompt answered for the user. On the user's data, NordPass was the Electron app's only extension: five profiles had it, each installed seconds after it was opened, and the other six still had it pending.

The migration now leaves extensions behind, and the app reinstalls none (`MigratedExtensions` is gone). A profile adds its own from the Web Store; the extension's saved data is still in the copied partition, so adding it back where it was used finds it. Installing it in one profile chosen for the user was rejected: the Electron app recorded none, and its storage existed in every profile. A `migration.json` written before keeps its `pendingExtensions`, which nothing reads now, and extensions the migration already installed stay until removed in each profile.

`extensions-per-profile` installs Dark Reader in one profile and checks that another, opened beside it, lists none and has no `Extensions/` entry for it, and that disabling, unpinning, and removing it in the first leave the second's own copy as it was. It passed before the fix too, which rules out the engine and the app's lists. `migration` opens both migrated profiles and expects neither to have the Electron app's extension; before the fix it found it in both.
