# Every Chrome dialog, bubble, and menu of a tab is a request the app answers

Every dialog, bubble, and menu Chrome would show for a Pane tab reaches the app as a request object, and the app answers it: in host mode Chrome shows no UI of its own (ADR 0004), so the app decides how each request looks. The requests are declared in `engine/pane/public/PaneDialogs.h`: JavaScript dialogs (beforeunload and form resubmission among them), permission requests, HTTP and proxy authentication, context menus, file choosers, external protocols, and unresponsive pages. Each reaches the app through a delegate method and is answered once. The engine withdraws a request (`didDismissRequest:`) when Chrome takes it back, and when its page goes (ADR 0074). The few surfaces that stay Chrome's are ADR 0022's.

The app shows the requests one at a time, and only for the selected tab, as Chrome's tab-modal dialogs do (`app/Pane/Browser/DialogPresenter.swift`): switching tabs puts a dialog back in line, and behind the PIN lock they wait (ADR 0042). They began as sheets on the window and are now drawn in it (ADR 0080); the file chooser stays the system's panel.

Chrome's UI reaches the app through the hooks of `engine/patches/0004-pane-ui-hooks.patch`, declared in `engine/pane/browser/ui/ui_hooks.h`: `CreatePermissionPrompt`, `LoginHandler::Create`, `ExternalProtocolHandler::RunExternalProtocolDialog`, DevTools docking in `DevToolsWindow` (ADR 0024), `PrintViewManagerBase::ScriptedPrint` for the app's print callback (ADR 0023), and `chrome::ShowDeviceChooserDialog`. JavaScript dialogs, the context menu, unresponsive pages, form resubmission, and screen-capture requests need no patch: they are `WebContentsDelegate` methods, which `HostedWebContentsDelegate` overrides. File dialogs go through `ui::SelectFileDialog::SetFactory`, which catches every file dialog Chrome opens for a window: file inputs, File System Access pickers, and Save As.

Ardia's hooks (task 3.2) were weighed against these seams. `chromium-password-bubble-hook` and `chromium-autofill-address-bubble-window` are not needed, with the password manager and autofill off, and neither is `chromium-cast-dialog-hook`, with the Media Router off (ADR 0022). `chromium-device-chooser-hook` is adapted as `g_pane_device_chooser`, which declines. `chromium-side-panel-hook` was left for extension side panels (Phase 4). The `chromium-devtools-*` seam gives way to Pane's own docking hooks, which also cover undocked DevTools.

Each kind of request has its scenario: `dialog-alert`, `dialog-confirm`, `dialog-prompt`, `dialog-beforeunload`, `dialog-form-resubmission`, `permission-prompt`, `http-auth`, `proxy-auth`, `context-menu`, `file-chooser`, `external-protocol`, and `hung-renderer`. `dialog-tab-closed` checks that a pending dialog goes with its tab.
