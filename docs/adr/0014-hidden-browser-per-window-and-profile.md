# One hidden Chrome Browser per window and profile

> **On the Views line** (`docs/plans/views-migration.md`, K3): Pane's views draw the window (ADR 0124), and the window layer kept only what they use: `WindowHost` (`pane/browser/ui/window_host.cc`) takes Pane's UI as its delegate, always, and `HostedBrowserWindow` (`browser_window.cc`) answers Chrome from it; the Swift app's constructor, its `NSView` in a `NativeViewHost`, and the Objective-C delegate are gone, and the TabBridge, which tied each tab to the Swift app's object for it, is `HostedTab` (`hosted_tab.cc`): how a page opened the tab, its id in traces, and the Web Store's buttons (ADR 0076).

Each Pane window holds one hidden Chrome `Browser` for each profile it shows, so pages, popups, and extensions see real tabs in a real browser window while the app draws everything on screen (ADR 0004). The Browser is backed by `pane::HostedBrowserWindow` (`pane/browser/ui/browser_window.{h,mm}`), adapted from Ardia's `ac_browser_window` (Apache-2.0, `third_party/ardia`), and the window's `WindowHost` makes a profile's Browser the first time the window needs it. Chrome counts that Browser as the current window for popups and service workers, so Ardia's hidden-window hooks are not needed (ADR 0031). Browsers Chrome makes itself, which got Chrome's own window at first, are folded into Pane's (ADR 0015), and undocked DevTools get a window of Pane's (ADR 0024).

A Browser stops counting as Pane's with its window. The registry of Pane's Browsers was emptied only by their WebContentsDelegate, which a Browser whose window had lost its host never got. Now the window forgets its Browser itself, last, as it is destroyed, so a later Browser at the same address is not taken for Pane's. The same teardown first closes the Browser's extension popups (ADR 0031).
