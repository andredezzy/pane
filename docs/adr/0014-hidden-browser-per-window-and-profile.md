# One hidden Chrome Browser per window and profile

Each Pane window holds one hidden Chrome `Browser` for each profile it shows, so pages, popups, and extensions see real tabs in a real browser window while the app draws everything on screen (ADR 0004). The Browser is backed by `pane::HostedBrowserWindow` (`engine/pane/browser/ui/browser_window.{h,mm}`), adapted from Ardia's `ac_browser_window` (Apache-2.0, `third_party/ardia`), and the window's `WindowHost` makes a profile's Browser the first time the window needs it. Chrome counts that Browser as the current window for popups and service workers, so Ardia's hidden-window hooks are not needed (ADR 0031). Browsers Chrome makes itself, such as one from an extension's `chrome.windows.create`, got Chrome's own window at first; their tabs now move into the profile's Browser in the Pane window (ADR 0015), and undocked DevTools get a window of Pane's (ADR 0024).

A Browser stops counting as Pane's with its window (A4 of the engine review, 2026-10-28). The registry of Pane's Browsers was emptied only by their WebContentsDelegate, which a Browser whose window had lost its host never got. Now the window forgets its Browser itself, last, as it is destroyed, so a later Browser at the same address is not taken for Pane's. The same teardown first closes the Browser's extension popups (ADR 0032).
