# One hidden Chrome Browser per window and profile

Each Pane window holds one hidden Chrome `Browser` for each profile it shows, so pages, popups, and extensions see real tabs in a real browser window while Pane's views draw everything on screen (ADRs 0004 and 0124). The window's `WindowHost` (`pane/browser/ui/window_host.cc`) makes a profile's Browser the first time the window needs it and tells Pane's UI, its delegate, what each Browser does (`WindowHost::Delegate`). Each Browser is backed by `pane::HostedBrowserWindow` (`pane/browser/ui/browser_window.{h,cc}`), adapted from Ardia's `ac_browser_window` (Apache-2.0, `third_party/ardia`), which answers Chrome from Pane's window, with no `BrowserView`. Each tab carries a `HostedTab` (`hosted_tab.cc`): how a page opened it, its id in traces, and the Web Store's buttons (ADR 0076). Chrome counts that Browser as the current window for popups and service workers, so Ardia's hidden-window hooks are not needed (ADR 0031). Browsers Chrome makes itself, which got Chrome's own window at first, are folded into Pane's (ADR 0015), and undocked DevTools get a window of Pane's (ADR 0024).

The UI's move into Views kept it (ADR 0124, U1): Pane's sidebar shows every profile at once, where Aside overwrites `Browser::profile_` in place and shows one profile at a time.

A Browser stops counting as Pane's with its window. The registry of Pane's Browsers was emptied only by their WebContentsDelegate, which a Browser whose window had lost its host never got. Now the window forgets its Browser itself, last, as it is destroyed, so a later Browser at the same address is not taken for Pane's. The same teardown first closes the Browser's extension popups (ADR 0031).

**Until 0.20.0** the Swift app drew the window: the Widget held its `NSView` in a `NativeViewHost`, an Objective-C delegate heard the window layer, and a `TabBridge` tied each tab to the Swift app's object for it, of which `HostedTab` is what is left.
