# packaging/VERSION is the one version source

Pane's version lives in `packaging/VERSION` alone, and the build writes it over the Chromium version the engine's bundle carries, so Finder, the About panel, Settings, the update check, and the dmg's name all give Pane's. `scripts/package.sh` writes it into the bundle's Info.plist as `CFBundleShortVersionString`, `CFBundleVersion`, and `PaneVersion`, and `scripts/dist.sh` names the dmg after it, `Pane-<version>-arm64.dmg`. Settings shows `PaneVersion`, and the update check compares it with the latest release's (ADR 0002). The Release workflow refuses a tag other than `v<version>` (AGENTS.md).

The bundle is the engine's, and its version keys were Chromium's (156.0.8078.48), which Finder and the About panel showed as Pane's. The Electron app set both keys to its own version, and Pane does too. Chromium does not depend on them: it reads the outer bundle's `CFBundleShortVersionString` only as a fallback, when a web app shim looks for an old-style framework layout, and its upgrade detector reads it only with Google's updater, which this build leaves out (`updater_no_updater`). Crashpad reads the framework's own plist.

Beside the version, `package.sh` records the commit the app was built from (`PaneCommit`) and its engine's key (`PaneEngineKey`, the one `build.sh` recorded, or the checkout's), by which a crash report's engine symbols are found (ADR 0047, `docs/building.md`). It also rewrites each `InfoPlist.strings`, so what macOS shows from the bundle's own words says Pane: the camera, microphone, location, Bluetooth, and passkey prompts, which Chromium's strings word "Once Chromium has access…", in every language, and the About panel's copyright, which credits Chromium.

**On Windows** (2026-11-15, commit `220a9c7`) the version is a file beside chrome.dll, `pane-version`, which `scripts/package-win.sh` writes from `packaging/VERSION` as it lays the app's folder out, and `pane/app/version_win.cc` reads from `base::DIR_ASSETS`: About Pane, Settings, and the update check give it. Chromium's own version stays the engine's there, in `chrome/VERSION`: a version folder, the files' version resources, and what the web sees name it, and Pane's own install needs no version of Chromium's of its own (the research before Pane's own install was chosen: a patched `chrome/VERSION` for each release would rename the Mac's framework folder and change the engine key at every release). A build not packaged, `out/Win`'s or a test copy from it, has no file and reads 0.0.0, as the Mac's `out/Release` does. Checked by `VersionWinTest` in `pane_unittests` on Windows, and a package laid out in the test VM, which reads its version.

The version carries on the Electron app's line. It started at that app's 0.6.0, and the first native release bumped it to 0.7.0 (ADR 0051). Every release starts with a semver bump; a local build without one overwrites the last dmg of that name (AGENTS.md).
