# Extension actions and popups behave as Chrome's

An extension's toolbar action and its popup behave as they do in Chrome, the browser extensions are written for: the engine keeps Chrome's per-tab action state and popup sizing, and the app shows the popup's page in its own popover (`app/Pane/Extensions/ExtensionPopover.swift`). Where the actions sit, pinned or in the extensions menu, is ADR 0054's.

An action's title, badge, icon, and popup are per tab. The engine reports them again when the profile's selected tab changes, through a `BrowserTabStripTracker` (`engine/pane/browser/extensions/extensions_bridge.mm`). Chrome's `ExtensionActionIconFactory` keeps the first default icon it returns, which is a blank placeholder when asked before the icon file loaded (NordPass's showed blank), so the bridge starts its factories over once an icon loads.

A popup's page sizes itself, as in Chrome: auto-resize is enabled on the popup's main frame as it becomes the main one (`RenderFrameHostChanged`, in `engine/pane/browser/extensions/action_popup.mm`), since its first document commits in a new frame. The page sits on an opaque white canvas in the popover: straight on the popover's material it was blended with it (vibrancy), and a dark popup turned near black. Under the Dark theme the page's view painted nothing at all, so that view alone takes the aqua appearance; the popover around it stays dark, and the page's color scheme follows the theme app-wide.

Some extensions turn their popup off until the user signs in. 1Password clears its popup seconds after installing, so its button opens its welcome page in a tab, as in Chrome. The `password-managers` scenario presses the button and checks whichever the extension chose.

A popup closes with its `Browser` (the engine review's B3). It held a raw `Browser*` and kept itself alive until closed; it now holds a weak pointer, and the Browser's window closes its popups as it is destroyed, telling the app. The `tabs-api` scenario deletes a profile with its popup open: before, the app died there in each of three runs, on an uncaught exception in NSWindow's restorable-state encoding 130 ms after the popup's close, and now the popup closes with the Browser. The same scenario opens the popup from the extension's worker with `chrome.action.openPopup`. The fix's other half, a Browser that stops counting as Pane's with its window, is ADR 0014's.
