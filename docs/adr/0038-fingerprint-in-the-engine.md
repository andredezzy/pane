# The fingerprint lives in Blink and the browser, not in script

Pane spoofs a profile's fingerprint inside the engine, in Blink and in the browser (patch `engine/patches/0006-pane-fingerprint.patch`), not from a page script as the Electron app did, so every surface is a native function, in every frame and worker, from the page's first script. The app builds each profile's `EngineFingerprint` (`app/PaneKit/Sources/PaneKit/EngineFingerprint.swift`) and hands it to the engine before the profile opens (`-[PaneBrowserApplication setFingerprint:forContextIdentifier:]`).

In the browser, content gets per-context hooks, `GetUserAgentForBrowserContext` and `GetUserAgentMetadataForBrowserContext`, and every place that asked for the global User-Agent uses them: renderer init; navigations, redirects included; service and shared workers; the per-profile Client Hints delegate; and the profile's network context, for prefetches and the browser's own requests. Languages use Chrome's own prefs: `intl.selected_languages`, from which `LanguagePrefs` derives `intl.accept_languages`. Setting the derived pref alone was reverted at once.

In the renderer, each renderer of the profile gets the renderer half of the fingerprint as `--pane-fingerprint`, and a renderer never serves two profiles. Blink's `PaneFingerprint` reads it once and reports navigator.platform, hardwareConcurrency, deviceMemory, and maxTouchPoints; the screen rectangles, colorDepth, and isExtended, plus devicePixelRatio; WebGL's unmasked vendor and renderer; and the speech voices. It adds canvas noise on getImageData, toDataURL, toBlob, and convertToBlob, the same noise on every path, and audio noise on an OfflineAudioContext's rendered buffer before the page gets it. Chromium 157 resolves `startRendering()`'s promise per rendered chunk (`OfflineAudioContext::OnChunkRendered`), before the completion event, so the noise is applied there, ahead of both; on 156 it came before `oncomplete`. The fingerprint's time zone becomes the renderer's host time zone: the system's changes no longer replace it, and DevTools' override still works on top. Its locale becomes the embedder locale of `LocaleController`, so it is the default locale of Intl. The renderer's `--lang` is unchanged, because a locale without a resource pak would crash it.

Where it differs from the Electron spoof, it does so on purpose. The GREASE brand order is Chromium's current one, a permutation seeded by the major version (`GetRandomOrder`). The Electron port's insertion index matches older Chrome only: it agrees for 136 and 156 by chance, and not for 157. PaneKit's `ClientHintsTests` check the derivation against the `Sec-CH-UA` that Google Chrome 120, 124, 131, and 136 sent, and the `fingerprint` scenario checks that the GREASE brand equals the engine's own. The full version list carries the engine's full version, and the User-Agent is reduced (`Chrome/156.0.0.0` on 156), where the Electron one was full. Device memory is reported in Chrome's buckets, a power of two from 0.25 to 8. The speech voices are hidden only when the claimed platform is not macOS, since the host's voices are a Mac's; the Electron app always hid them. There are no script stubs: chrome.app, loadTimes, csi, plugins, and storage estimates are Chrome's own. There is no Worker wrapper: every worker reads Blink directly, including the module and cross-origin workers that the Electron app's wrapper skipped. The noise seed and algorithms are the Electron app's, so a migrated profile draws the same canvases.

A changed fingerprint reaches navigations and new renderers at once; an open page keeps its renderer's values until it reloads in a new process. So the profile sheet's fingerprint editor, on a change to an open profile, releases its pages and loads the selected one again, and the engine shuts down the profile's spare renderers, which started with the old fingerprint.

The known gaps are the Electron app's: WebGPU's adapter info, the CSS `device-width` and `resolution` media features, `window.outerWidth` against a smaller claimed screen, and the `Sec-CH-Device-Memory` header. Service workers' own fetches carry no UA Client Hints in Chrome, and an unfingerprinted profile's carry none either; they carry only the User-Agent, which is the profile's. What a profile reveals through Chrome's own requests, outside its pages, is ADR 0040's.
