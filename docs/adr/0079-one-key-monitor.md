# One key monitor, in drawing order

> **On the Views line** (`docs/plans/views-migration.md`, H7): no key monitor. The overlay on top holds the keys (Quit Pane?'s and the App icon picker's dialogs), Esc and Return are its own, the command table is the window's FocusManager's accelerators and the menu bar's, and page first or app first is `PreHandleKeyboardEvent`; the switcher keeps the focus where it was, as the Swift's did, its Esc and Ctrl's release coming from the page through `PreHandleKeyboardEvent` and from Views through a handler ahead of the focused view. `KeyRouter.swift` is gone; PaneKit's `KeyRouting` stays, the order and keys the PIN screen (L1) and the extensions' overlays (X1, X3, X5) port from. `key-precedence` checks Quit Pane? over the App icon picker; over the extensions menu waits for X1.

> **On the Views line** (`docs/plans/views-migration.md`, What Chrome asks for): on the Mac, Views hands a key to the focused view before the FocusManager's accelerators, and the address takes Esc and Return itself, so a page's dialog takes its two from a handler on the window's root view, ahead of whatever has the keys, as `KeyRouting`'s dialog layer did; it stands aside while the switcher, Quit Pane?, or the App icon picker shows over it.

Pane has one key monitor, and it offers each key to the overlays that show in the order they are drawn, topmost first, so the overlay on top answers a key before the one under it. Before, the PIN screen's, Quit Pane?'s, the extensions', and the switcher's monitors each decided alone, in an order AppKit does not document.

`KeyRouter` (`app/Pane/Browser/KeyRouter.swift`) is the one monitor, a local event monitor: it sees every key before any view, a page included, and before the menu bar's shortcuts. PaneKit's `KeyRouting` decides, as a pure function of what shows: the PIN screen (ADR 0042), Quit Pane? (ADR 0053), the App icon picker (ADR 0089), the Keyboard shortcuts dialog and its field recording a key (ADR 0098), Add a site (ADR 0062), an extension's popup, the extensions menu and an extension's more menu, the switcher, a page's dialog (ADR 0021), a page's fullscreen. The first that takes a key ends it; a key they all leave may be an extension's shortcut, which goes before the page (ADR 0098). Key codes are named (`KeyCode`), and 16 tests cover the routing.

`key-precedence`, where the run lets Pane take the front (ADR 0012), opens the extensions menu and Quit Pane? over it, in both orders, and presses Esc twice. Before, with the menu first, one Esc closed the menu hidden under the panel and Quit Pane? stayed; now Quit Pane? goes first, then the menu.
