# Pane 0.7.0 is the first native release, and the Electron app is retired

Pane 0.7.0, published on 2026-10-28, is the first native release, a minor bump from the Electron app's 0.6.0, and with it the Electron app is retired (the user's call: every Electron user moves to the native app). The `electron` branch, at `Release 0.6.0`, keeps the Electron app as a backup and is not maintained. 0.7.0 is built on Chromium 157.0.8103.15, on `engine-0d0a01f8c703`. Every Electron Pane's update check (`updater.ts` on `electron`) reads `releases/latest` at launch and once a day, finds 0.7.0 newer than its own version, and offers the `-arm64.dmg`, which one click downloads and opens in Finder (ADR 0002). The native app then migrates the Electron app's data (ADR 0043).

The release was first published that day as v1.0.0, a major bump for the move off Electron, built by the Release workflow from `05a119b`. It is withdrawn, its GitHub release and its tag deleted (the user's call: Pane is not 1.0.0 yet). 0.7.0 carries the app as `main` has it at the `Release 0.7.0` commit, on the same engine, with 1.0.0's release notes and the number changed. A version is never reused: the next release was to be 0.7.1 or 0.8.0, whatever this one turned out to need. Whoever installed 1.0.0 is offered nothing until a release passes 1.0.0, since the update check only offers a newer version (ADR 0002): they install 0.7.0 from its dmg over it, and their data stays, under the same bundle ID. 1.0.0's dmg was downloaded once, by the user.

The Electron app left the native app's branch first, `main` keeping it until the merge. `apps/veil` went with all six packages: `electron-chrome-extensions`, `electron-chrome-context-menu`, and `ui` served only the Electron app, and `config-typescript`, `config-tsdown`, and `config-test` only configured those packages. Turbo and its helper scripts (`turbos`, `filter`, the postinstall build) went with the workspaces they ran. The gates that remain are `bun run lint` (Biome and ESLint, over the scenario runner), `bun run typecheck`, which now covers the scenario runner, never type-checked before, `bun run test` (PaneKit's `swift test`), and `bun run knip`. Electron 41.4.0 stays as a root dev dependency: the `migration` scenario seeds the Electron app's data with the version it shipped, which users upgrading from it still need. Comments that cite `apps/veil` name the Electron source a feature was ported from, which the `electron` branch keeps. Cleaning `main` of what the Electron app left is ADR 0086's.

`release.yml` is one job on the `xcode-27` runner (ADR 0049). It checks the tag against `app/VERSION` (ADR 0044) and that its commit is on `main`, runs PaneKit's tests, builds the dmg on the prebuilt engine, and publishes it. Since 0.13.0 it also attests the dmg's build provenance (`gh attestation verify <dmg> --repo andredezzy/pane`), publishes the app's symbols beside it (`Pane-<version>-arm64.dSYM.zip`, ADR 0047), and opens the generated notes with the Chromium the release is built on. The Electron matrix's Windows, Linux, and Intel Mac builds ended with it, since Pane is macOS on Apple Silicon (ADR 0004); the update check already read only the arm64 dmg.

What was rejected:

- **Keeping 1.0.0:** the user's call.
- **Turning v1.0.0 into a draft or a prerelease:** the update check, reading `releases/latest`, would stop seeing it, but the tag would stay public, and the version line would still have to pass 1.0.0 before anyone who installed it was offered an update.

How it is checked:

- **As users get it, before the tag:** every Electron Pane offers the update the moment a native release is the latest, so it was tried first. A dry run of the Release workflow (`workflow_dispatch` keeps the dmg as an artifact and publishes nothing) built 1.0.0's commit, and the dmg `engine/scripts/dist.sh` built from the `Release 0.7.0` commit; each app, out of its dmg, passed `smoke`, `hosted`, `migration` (profiles, tabs, PIN, and site data, with the Electron app's files untouched and nothing written while it ran), and `updates`.
- **The published release:** the dmg's signature, version, and minimum macOS were checked. The Release workflow's tag check (ADR 0044) holds the tag to `app/VERSION`, and `releases/latest` gives v0.7.0 and its `Pane-0.7.0-arm64.dmg`, with no v1.0.0 release or tag left on GitHub.
- **The notes** say what the move asks of a user: quit the old Pane, replace it, allow the old app's keychain item, add extensions again, and, since Pane is not notarized (ADR 0048), choose Open Anyway when Gatekeeper stops it. They name the minimum, macOS 14 on Apple silicon (ADR 0085).
