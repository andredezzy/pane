# Pane 1.0.0 is the native app, and the Electron app is retired

> **Its version is replaced by [ADR 0088](0088-first-native-release-is-0-7-0.md)**: the first native release is 0.7.0, and v1.0.0 is withdrawn. The rest stands.

Pane 1.0.0, published on 2026-10-28, is the first native release, and with it the Electron app is retired (the user's call: every Electron user moves to the native app). The `electron` branch, at `Release 0.6.0`, keeps the Electron app as a backup and is not maintained. 1.0.0 is a major bump under the AGENTS.md rule, for the move off Electron, on Chromium 157.0.8103.15. The Release workflow built it from `05a119b` on `engine-0d0a01f8c703`, and it is the latest release. Every Electron Pane's update check (`updater.ts` on `electron`) reads `releases/latest` at launch and once a day, finds 1.0.0 newer than its own version, and offers the `-arm64.dmg`, which one click downloads and opens in Finder (ADR 0002). The native app then migrates the Electron app's data (ADR 0043).

The Electron app left the native app's branch first, `main` keeping it until the merge. `apps/veil` went with all six packages: `electron-chrome-extensions`, `electron-chrome-context-menu`, and `ui` served only the Electron app, and `config-typescript`, `config-tsdown`, and `config-test` only configured those packages. Turbo and its helper scripts (`turbos`, `filter`, the postinstall build) went with the workspaces they ran. The gates that remain are `bun run lint` (Biome and ESLint, over the scenario runner), `bun run typecheck`, which now covers the scenario runner, never type-checked before, `bun run test` (PaneKit's `swift test`), and `bun run knip`. Electron 41.4.0 stays as a root dev dependency: the `migration` scenario seeds the Electron app's data with the version it shipped, which users upgrading from it still need. Comments that cite `apps/veil` name the Electron source a feature was ported from, which the `electron` branch keeps.

`release.yml` is one job on the `xcode-27` runner (ADR 0050). It checks the tag against `app/VERSION` (ADR 0044), runs PaneKit's tests, builds the dmg on the prebuilt engine, and publishes it. The Electron matrix's Windows, Linux, and Intel Mac builds ended with it, since Pane is macOS on Apple Silicon (ADR 0004); the update check already read only the arm64 dmg.

Every Electron Pane offers the update the moment v1.0.0 is the latest release, so the release was tried first as users get it. A dry run of the Release workflow (`workflow_dispatch` keeps the dmg as an artifact and publishes nothing) built the same commit, and its app, out of the dmg, passed `smoke`, `hosted`, `migration` (profiles, tabs, PIN, and site data, with the Electron app's files untouched and nothing written while it ran), and `updates`. The published dmg's signature, version, and minimum macOS were checked. The release notes say what the move asks of a user: quit the old Pane, replace it, allow the old app's keychain item, add extensions again, and, since Pane is not notarized (ADR 0048), choose Open Anyway when Gatekeeper stops it. They name the minimum, macOS 14 on Apple silicon (ADR 0085). Cleaning `main` of what the Electron app left is ADR 0086's.
